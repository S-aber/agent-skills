- # 基于 Tools + Skills + MCP 的 Agent 工作流替代方案

  ## 1. 背景与目标

  ### 1.1 原有工作流系统概述

  - 工作流引擎架构（DAG 节点编排模型）
  - 已有节点类型：模型调用节点、多模态大模型调用节点、知识库检索节点、语音识别节点、文档解析节点、代码执行节点等

  ### 1.2 Bash 权限问题的决策

  - 安全评审结论：禁止 LLM **直接**执行 Bash 命令或调用系统 Shell。
  - MCP 服务端在执行预定义能力（如文档解析、语音识别）时，可以在受控的沙箱或容器内使用必要的系统级操作，这些操作不视为越权，前提是 MCP 服务已通过安全审核且被显式授权。
  - 授权模型：MCP 服务拥有独立的权限声明，Agent 只能调用已注册且当前用户/租户被允许的 MCP 服务，不允许 LLM 自行构造或调用未注册的系统命令。
  - 影响范围：工作流中原直接依赖 Bash 的节点需全部替换为 MCP 服务或内置 Tool。

  ### 1.3 替代方案的核心思路

  - 用 Tools + Skills + MCP 三层体系替代传统 DAG 工作流引擎
  - LLM 作为编排器，对话历史作为数据总线
  - Skill 作为纯知识/流程模板，指导 LLM 如何组合 Tool 与 MCP
  - 参考项目：claude-code-ts 架构

  ------

  ## 2. 架构总览

  ### 2.1 整体架构图

  - LLM 编排层：Agent Loop 自主决策 Tool 调用顺序，并根据上下文动态激活 Skill
  - Tool 层：内置原子能力（只读、代码执行等）
  - MCP 服务层：外部专业能力接入（知识检索、ASR、文档解析等），每个 MCP Server 运行在独立沙箱中
  - Skill 知识层：领域知识与流程指引，纯描述，不包含可执行代码

  ### 2.2 与旧工作流的对比

  | 维度     | 旧工作流       | 新方案                          |
  | :------- | :------------- | :------------------------------ |
  | 编排方式 | DAG 显式连线   | LLM 上下文推理 + Skill 指导     |
  | 数据传递 | 模板变量替换   | 对话历史自动适配 + 可选映射规则 |
  | 流程定义 | 画布拖拽       | SKILL.md 自然语言描述           |
  | 能力扩展 | 开发新节点     | 编写 MCP Server 或 Tool         |
  | 权限控制 | 节点级别硬限制 | LLM 禁止 Bash，MCP 服务自主授权 |

  ------

  ## 3. Tool 体系设计

  ### 3.1 内置 Tool 清单

  - `read_file`：读取文件内容（文本/图片/PDF），只读
  - `web_search`：网络搜索，只读
  - `web_fetch`：网页内容获取，只读
  - `execute_python`：代码沙箱执行，可运行预置模板或临时脚本
  - `Skill`：技能调用（将 Skill 内容注入上下文，实际执行仍由其他 Tool 完成）

  ### 3.2 Tool 注册与发现机制

  - `ToolRegistry` 统一管理
  - 内置 Tool 启动时自动注册
  - MCP Tool 通过 MCP Client 动态发现与注册
  - Skill Tool 根据 LLM 的激活状态动态注入系统提示，不注册独立可执行单元

  ### 3.3 Tool 接口规范

  - 输入：JSON Schema 定义参数
  - 输出：`content` + `is_error`
  - 权限声明：`is_read_only`、`check_permissions`
  - 转换为 LLM API 格式（OpenAI function calling / Anthropic tool use）

  ### 3.4 移除的 Tool

  - `execute_bash`：安全策略禁止
  - `write_file`：工作流场景无写入需求
  - 其他写/删类 Tool：最小权限原则

  ------

  ## 4. Skill 体系设计

  ### 4.1 SKILL.md 规范

  - YAML frontmatter：`name`、`description`、`allowed-tools`、`model` 等
  - Markdown 指令体：自然语言流程描述 + 参数提取指引 + 异常处理策略
  - 参数声明与注入说明

  **Skill 的定位与激活**

  - Skill 是纯知识/流程模板，不含可执行代码。
  - 它描述完成某类任务的“最佳路径”：应依次调用哪些 Tool/MCP、如何从上下文提取参数等。
  - Skill 本身不调用 Tool，而是注入到对话上下文，**由 LLM 根据当前用户意图自主决定是否激活**。无需额外路由服务，LLM 根据 Skill 的 `description` 和任务相似度自行选择。
  - 用户也可通过 `@skill-name` 显式激活。
  - 激活后，Skill 内容以系统提示形式注入当前对话，后续 Tool 调用受其指导。若 LLM 判断不再需要，可自动停止遵循（去激活），Skill 内容随之回收。

  ### 4.2 代码模板与参数注入机制

  - 对于需要自定义代码执行的旧节点，其代码逻辑封装为 `execute_python` Tool 的预置模板。

  - Skill 中可引用模板：“使用 execute_python 工具，加载模板 `clean_data_v1`，将上一步的 csv_content 作为输入”。

  - 参数映射规则（可选）：Skill 中可声明结构化映射，用于关键业务场景的确定性提取。

    yaml

    ```
    input_mapping:
      from_previous_tool: document_parser
      extract:
        revenue: "$.finance.revenue"
        profit: "$.finance.net_profit"
    ```

    

    框架优先按规则提取，失败时回退到 LLM 理解。既保留灵活性，又降低出错概率。

  ### 4.3 Skill 激活与生命周期

  - 用户手动激活 / 对话上下文自动激活
  - Skill 内容注入时机（inline / fork）
  - 去激活条件：LLM 判断任务切换或用户显式退出
  - 上下文回收策略

  ### 4.4 Skill 存储与版本管理

  - 存储后端设计
  - 版本控制（Git 友好，纯文本差异）
  - 导入导出

  ------

  ## 5. MCP 服务层设计

  ### 5.1 MCP Client 架构

  - 传输层支持（stdio / SSE / HTTP）
  - 连接管理与心跳
  - 服务注册与发现（`tools/list`、`prompts/list`、`resources/list`）

  ### 5.2 外部能力接入规范

  - 知识库检索服务：向量检索 + RAG
  - 语音识别服务：ASR 引擎接入（Whisper 等）
  - 文档解析服务：docx、pdf、xlsx 等格式解析
  - 多模态调用服务：图片理解、视频分析

  ### 5.3 MCP Tool 自动注册与权限

  - 发现后注入 `ToolRegistry`
  - 命名规范（避免与内置 Tool 冲突），建议前缀 `mcp__`
  - **权限模型**：能发现并注册的 MCP Tool，即代表当前用户/租户拥有其使用权。Agent 框架不再做额外权限校验，但需记录调用日志用于审计。
  - 若 Skill 依赖特定 MCP 服务，可在 `allowed-tools` 中声明，LLM 据此判断是否可执行。

  ### 5.4 服务认证与安全隔离

  - MCP Server 身份认证
  - 请求级鉴权（可选 mTLS）
  - 独立进程/容器运行，资源限制

  ------

  ## 6. Agent 编排引擎

  ### 6.1 Agent Loop 设计

  - 用户输入 → 构建消息上下文（含已激活 Skill） → 调用 LLM → 解析 Tool 调用 → 执行 Tool → 追加结果 → 继续循环
  - 最大 Tool 调用次数限制
  - Token 预算管理

  ### 6.2 对话历史作为数据总线

  - 上一节点输出自动进入上下文，无需显式连线
  - **默认模式**：LLM 自主解析输出并提取所需参数
  - **Skill 指导模式（推荐）**：Skill 中可声明参数映射规则（如 JSONPath），框架优先按规则提取并校验类型，失败时再由 LLM 修复或提请人工确认。该模式显著降低提取错误，且便于审计。

  ### 6.3 多轮 Tool 调用流程

  - Tool 调用识别与解析
  - 并发与串行执行策略（框架需支持 Skill 中描述的“同时调用 A 和 B，等待返回”）
  - Tool 执行错误的处理与重试

  ### 6.4 中断与恢复机制

  - 需用户确认时的挂起（如关键参数填充）
  - 长时间任务的异步执行
  - 会话恢复

  ------

  ## 7. 安全设计

  ### 7.1 Tool 最小权限原则

  - 不提供 Bash/写入/删除类 Tool
  - 只读优先
  - Tool 级别权限声明

  ### 7.2 代码沙箱限制

  - 文件系统访问范围限制
  - 网络访问控制
  - 系统调用白名单
  - 资源配额（CPU、内存、执行时间）

  ### 7.3 MCP 服务级别鉴权

  - 服务间 mTLS（可选）
  - 按用户/租户的访问控制（由管理端绑定）
  - 敏感操作的审计日志

  ### 7.4 速率限制与资源保护

  - 单用户并发限制
  - API 调用频率限制
  - 成本控制

  ------

  ## 8. 前端交互

  ### 8.1 工作流创建界面改造

  - 从 DAG 画布 → Skill 编辑器 + MCP 配置面板
  - SKILL.md 可视化编辑（分屏预览）
  - Tool 能力目录浏览

  ### 8.2 Tool 调用实时展示

  - 调用链可视化（基于 Skill 指导的预期路径 vs 实际路径）
  - 输入输出预览
  - 执行状态（等待/执行中/完成/失败）

  ### 8.3 参数确认与干预点

  - 关键节点的确认弹窗（当映射规则校验失败或置信度低时）
  - 手动修正参数
  - 中止与重新执行

  ## 9. 兼容与迁移

  ### 9.1 旧工作流节点到新体系的映射表

  | 旧节点类型     | 新体系对应                                 |
  | :------------- | :----------------------------------------- |
  | 模型调用节点   | Agent Loop 本体                            |
  | 多模态调用节点 | MCP multimodal 服务                        |
  | 知识库检索节点 | MCP knowledge-search 服务                  |
  | 语音识别节点   | MCP asr 服务                               |
  | 文档解析节点   | MCP document-parser 服务                   |
  | 代码执行节点   | execute_python Tool（模板化）              |
  | 条件分支节点   | Skill 中自然语言描述 + 用户补全            |
  | 自定义代码节点 | 迁移为 execute_python 模板，Skill 指导调用 |

  ### 9.2 数据迁移方案

  - **自动转换范围**：线性流程、简单参数传递可直接转为 SKILL.md 草稿。
  - **人工干预场景**：
    - 条件分支：提供 `if/else` 分支描述模板，由用户将分支条件转写成自然语言。
    - 自定义代码执行节点：原代码由迁移工具提取为 `execute_python` 的预置模板，生成的 SKILL.md 中包含调用指引（如“使用模板 `clean_data_v1`”）。用户需复核沙箱兼容性。
    - 并行汇合：Skill 中描述“同时调用 Tool A 和 B，等待返回”，若框架暂不支持并发，可在模板中说明限制，引导改为串行。
  - 提供**迁移助手工具**：读取旧工作流 JSON，生成含占位符的 SKILL.md，高亮需用户填写的部分。
  - 验证与回滚策略

  ### 9.3 渐进式切换策略

  - 双轨运行期
  - 灰度策略
  - 切换时间线

  ------

  ## 10. 非功能需求

  ### 10.1 性能指标

  - LLM 首 Token 延迟
  - Tool 执行超时阈值
  - 并发会话数

  ### 10.2 可用性要求

  - 服务可用性 SLA
  - 降级策略（MCP 服务不可用时，Skill 可提供纯 LLM 替代方案）

  ### 10.3 扩展性要求

  - 新增 Tool 的开发工作量
  - 新增 MCP 服务的接入成本
  - 水平扩展能力

  ### 10.4 日志与监控

  - Agent 执行链路追踪（Trace ID 贯穿 LLM 调用、Tool 执行）
  - Tool 调用统计与 Skill 命中率
  - 错误率与延迟监控
  - 成本统计（按 Skill、用户维度）
